# Lens: Convergence-Divergence Lens
## Type: lens

## Description
Reframes any decision or analysis by forcing explicit choice between converging (standardizing, consolidating, following consensus) vs diverging (diversifying, exploring alternatives, breaking symmetry). The lens makes the convergence-divergence tradeoff visible and actionable.

## The Core Questions
When examining any system, decision, or pattern:
1. **Current State**: Is this system converging toward a single point, or diverging into multiple paths?
2. **Pressure**: What forces are pushing toward convergence/divergence?
3. **Optimal Choice**: Given the context, which direction has higher expected value?
4. **Timing**: Is this the RIGHT time to converge/diverge, or premature?

## Convergent Reframes
- "We should standardize on X" → "At what cost does standardization limit adaptation?"
- "Everyone agrees Y is best" → "Does consensus reflect wisdom or social pressure?"
- "One right answer" → "What does this framing exclude?"

## Divergent Reframes
- "We need more options" → "At what cost does exploration delay action?"
- "Diversity is valuable" → "Does this diversity create coordination costs?"
- "Many paths forward" → "Which paths are actually viable?"

## The Convergence-Divergence Matrix
```
                    Low Uncertainty    High Uncertainty
High Coordination      LOCK IN           EXPLORE
Low Coordination       SPRAWL            DIVERSE
```

## Application
1. Identify current system state (converging/diverging/stable)
2. Identify forces (economic, social, technical) pushing state
3. Apply matrix: where does this situation land?
4. Apply appropriate reframe based on quadrant
5. Assess: is current trajectory optimal?

## When to Apply
- Before committing to standards or frameworks
- When "everyone agrees" without analysis
- When facing decision paralysis from too many options
- When convergence pressure (symmetry) feels wrong
- When divergence pressure (complexity) feels unmanageable

## Output Shape
```markdown
## Convergence Analysis: {subject}

**Current State**: [converging/diverging/stable]
**Forces**: [what's pushing the system]
**Matrix Quadrant**: [lock-in/explore/sprawl/diverse]
**Optimal Direction**: [converge/diverge/both/mismatch]
**Recommendation**: [specific action]
**Warning Sign**: [when to reverse course]
```

## Example Transformation
**Before**: "Our team should use the same coding standard"
**After**: "Convergence Analysis: Coding Standards
- Current: partial convergence (some standards, inconsistent)
- Forces: tooling (auto-format), team size growth, onboarding needs
- Quadrant: LOCK IN (high coordination, moderate uncertainty)
- Optimal: CONVERGE on formatter + naming, DIVERGE on architecture choices
- Recommendation: enforce formatter, allow architectural experimentation
- Warning: if team shrinks or domain shifts, re-evaluate"

## Quality Indicator
The lens works when it reveals the convergence-divergence tradeoffs that were previously invisible. If your analysis didn't change direction or reveal a hidden tension, the lens wasn't applied deeply enough.
