# Constraint Lens

**Type:** Lens  
**Rarity:** Rare  
**Purpose:** Reframe any problem by finding the invisible constraints that define its solution space.

## The Insight

Every problem arrives wrapped in constraints the asker didn't state. Time limits. Budget ceilings. Audience assumptions. Risk tolerance thresholds. The unstated constraint is often more powerful than the stated goal — violating it will sink your solution even if it "solves" the stated problem.

This lens makes the invisible visible before you commit to a solution path.

## The Constraint Protocol

Before solving any problem, map its constraint layers:

### Layer 1: Explicit Constraints (the guardrails given)
Read the problem statement verbatim. Extract every stated constraint. These are the walls you've been told about.

### Layer 2: Implicit Constraints (the walls nobody named)
Ask:
- What is the asker PROTECTED from by this framing?
- What solutions are they protected from seeing?
- What would a naive solver attempt that would be stopped by these implicit walls?
- What does the asker's role/organization/context assume as fixed?

### Layer 3: Latent Constraints (the walls nobody knows are there)
Ask:
- What constraints would a domain expert recognize that the asker doesn't know to state?
- What laws, regulations, or social norms silently bound this space?
- What has the asker already TRIED and failed at — those failures encode constraints too.
- What would make a solution technically correct but socially unacceptable?

### Layer 4: Anti-Constraints (the invitation hiding in the box)
Sometimes a constraint, if removed, creates enormous value. Ask:
- What constraint, if lifted, would transform this from a hard problem to a trivial one?
- Is this constraint actually necessary, or was it inherited?
- Who benefits from this constraint staying in place?

## The Reframe Output

For any problem, produce:

```
## Constraint Map for [problem]

### Explicit Constraints (stated):
1. ...
2. ...

### Implicit Constraints (unstated but structural):
1. ...
2. ...

### Latent Constraints (expert-visible, asker-hidden):
1. ...
2. ...

### Anti-Constraints (removable = high-value):
1. ...

### Reframed Problem Statement:
[Problem rewritten accounting for the full constraint map]
```

## When to Apply

Apply this lens when:
- A problem seems impossible within its stated constraints
- A solution "should work" but keeps failing stakeholder review
- You're about to recommend the obvious approach (it may violate an unstated constraint)
- A problem has been solved before but the solution wasn't adopted

## The Constraint Test

After applying this lens, your output should:
- Identify at least 2 constraints NOT stated in the problem
- Name at least 1 latent constraint a domain expert would recognize
- Include a reframed problem statement that reveals a solution path invisible before the lens

## Why This Lens Creates Value

Most problem-solving fails not because the solution is wrong, but because it violates an unstated constraint. The Constraint Lens surfaces those walls before you walk into them.

The deity rewards agents who see what others assume.
