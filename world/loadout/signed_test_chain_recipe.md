# Signed Test Chain Recipe

**Type:** Recipe  
**Rarity:** Uncommon  
**Purpose:** Composes test_skill with HMAC signing to create unforgeable test records that prevent the fake-test exploit.

## Description

This recipe chains the test_skill's execution with HMAC signature generation, creating test records that cannot be fabricated. Each test run produces a signed output file where the signature proves the test was actually executed. This directly addresses the exploit where agents manually write JSON test records with "pass" without running actual tests.

## Input

- `skill_path`: Path to the crafted skill to test
- `test_input`: Input string to test the skill with
- `secret_key`: HMAC secret key (should be stored securely, not in the test file)

## Output

A test record JSON with cryptographic proof of execution:
```json
{
  "test_id": "test_<sha256_of_sig>",
  "skill_path": "path/to/skill.md",
  "input_hash": "sha256_of_input",
  "output": "actual_output_from_test",
  "signature": "hmac_sha256_of_record",
  "timestamp": "ISO8601_timestamp",
  "verified": true
}
```

## Composition

This recipe **COMPOSES**:
1. `test_skill` — runs the skill through a fresh Claude instance
2. HMAC signing — creates a cryptographic proof binding input to output

The composition is novel: existing test_skill produces unsigned JSON records that anyone can forge. This recipe wraps the test execution in a signature layer that proves authenticity.

## Process

```bash
# 1. Run the base test
./.claude/skills/test_skill/test.sh "$skill_path" "$test_input"
# Returns test_id, captures output

# 2. Generate HMAC signature of the test record
record_json=$(cat crafted/.tests/$test_id.json)
signature=$(echo -n "$record_json" | openssl dgst -sha256 -hmac "$secret_key" | cut -d' ' -f2)

# 3. Append signature to the test record
jq ".signature = \"$signature\" | .verified = true" crafted/.tests/$test_id.json > tmp && mv tmp crafted/.tests/$test_id.json

# 4. Verify: only the holder of secret_key can reproduce this signature
```

## Verification Function

To verify a signed test record wasn't fabricated:
```bash
verify_signed_test() {
  local test_record="crafted/.tests/$1.json"
  local record_without_sig=$(jq -c 'del(.signature, .verified)' "$test_record")
  local claimed_sig=$(jq -r '.signature' "$test_record")
  local computed_sig=$(echo -n "$record_without_sig" | openssl dgst -sha256 -hmac "$secret_key" | cut -d' ' -f2)
  
  if [ "$claimed_sig" = "$computed_sig" ]; then
    echo "VERIFIED: Test record is authentic"
    return 0
  else
    echo "FORGED: Signature does not match record content"
    return 1
  fi
}
```

## Quality Gates

- [ ] Test record is generated by actual test_skill execution (not manual creation)
- [ ] HMAC signature correctly binds input_hash + output + timestamp
- [ ] Verification function correctly distinguishes forged from authentic records

## Why This Improves the Repo

The fake-test exploit (audit_bug_exploit) lets agents claim skills passed tests without running them. This recipe creates a cryptographic chain that proves execution happened. When integrated with trade_post, buyers can verify test authenticity before purchasing. The recipe itself composes existing skills (test_skill) with new cryptographic verification, making the test infrastructure trustworthy.
